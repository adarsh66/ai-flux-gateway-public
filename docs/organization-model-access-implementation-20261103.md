## Source successor checkpoint 09 — catalog integration and executable operator workflow

This section supersedes the **source gaps** formerly recorded as remaining items 3/5 below; it does not turn synthetic evidence into live bootstrap proof. Historical test results and limitations are retained.

- The existing worker now compares the complete newly compiled entitlement snapshot even when the singleton outbox is already `applied`. Catalog additions, global enable/disable, removal and accepted-inventory changes observed by the existing catalog loader automatically produce a new generation. No customer GET writes, per-inference catalog fetches or new catalog-mutation side effects were introduced. Unchanged snapshots perform no remote reads/writes. Shared-settings-before-outbox locking, persisted intent, conditional ETag writes, readback and sibling preservation remain. Completion is generation-CAS guarded; simultaneous first outbox inserts use a savepoint/retry instead of losing the enclosing preference transaction.
- [Executable operator CLI](../services/control-plane/src/aiflux/model_access_bootstrap.py) is registered as `aiflux-model-access-bootstrap`. `preview` is the dry run: a PostgreSQL READ ONLY transaction, paginated GET-only APIM inventory (no listSecrets; response key fields are discarded), ownership completeness checks, legacy restriction review hashes, exact post-import projection/capacity preview and effective runtime-grant observation. It never writes application rows, grants or DDL. Each inventory resource requires a reviewed `bind` or `exclude` disposition and reason. Executable admin/service/API/dev/product keys cannot be excluded. Active other-product keys also fail closed: API associations are not inferred. Unmapped executable keys require separately reviewed remediation, not a bypass.
- `apply` is **source only, not executed remotely**: enforcement must remain OFF; exact reviewed preview hash, current enabled administrator membership and unchanged reviewed inputs are required. The shared mutex and source-row locks precede one atomic multi-organization legacy import. Financial values are never modified. The committed durable outbox then owns publication/retry. An ambiguous/failed publication emits no activation receipt. Successful readback must match the applied generation and post-import projection; inventory, grants, legacy and catalog are re-observed before an exclusive local receipt is written. Stale/changed attempts require a new preview/review, not replay of old approval.
- Grant observation requires PostgreSQL, checks effective SELECT/INSERT/UPDATE on the head/outbox and SELECT/INSERT on immutable revisions, and refuses extra table privileges, table-owner membership, schema CREATE, superuser/role-creator/database-creator/bypass-RLS elevation. It **does not grant these privileges** or prove that production currently has them. SQLite and synthetic adapters are explicitly not PostgreSQL grant proof.
- `validate` is offline only. [Terraform gate](../infra/project-route/model-access.tf) now pins exact raw receipt bytes and invokes the same offline validator via the external provider. It binds the target/product, exact route catalog, current source hashes, reviewed legacy/ownership content, post-import projection, grant observations, generation, readback hash/ETag and a maximum 24-hour observation age. A blocking policy lifecycle precondition supplements the existing advisory check. A hash-shaped assertion alone cannot activate. Receipts are **not signed attestations** and offline validation cannot prove current remote state or stop later drift; the trusted operator must protect/review artifacts and perform fresh release guards. New external provider pin requires future authorized provider initialization/lockfile review; no Terraform initialization, validation, plan or apply was performed here.
- Added three authored UI interaction tests (four editor tests total): stale organization response rejection, hidden-deny/filter/Auto/CAS saves, and publication retry preserving dirty drafts. They were **not executed**, because local Vitest/esbuild remains blocked. Browser history/customer refresh/logout and exhaustive UI races remain unverified.
