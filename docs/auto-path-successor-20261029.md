## Implemented stage adapter; still requires actual independent review

The operational stage adapter now verifies both original/candidate policy
representations, normalizes ONLY the verified temporary global hash in full13,
compares every other protected/inherited field, and reads the actual conditional
ETag last. Original global raw bytes must match exactly on restoration. Policy
PUTs, online/offline and reservation have separate permanent fsynced intents.
The captured owned API response includes `isOnline`. Its value may change only
to the explicit boolean independently read from the complete revision list;
every other owned API field must remain exact. An omitted or inconsistent flag
is never treated as proof of offline state.
Unknown outcomes consume the stage; cleanup can reconcile an already-original
state without sending another write. The Windows kernel stage lock releases on
process crash and prevents parallel parent/supervisor wire stages.

A separate parent-started supervisor records its real PID/creation identity and
bound manifest before any diagnostic/global write. Activation requires that
exact process to remain live. It waits for the parent's durable cleanup-request
or end-minus3minutes, then independently attempts offline, global restore and
diagnostic restore. It does not activate or Send. Activation stops at
end-minus5minutes, leaving the supervisor reserve. Cleanup bypasses window/review
age, never source/ownership/ETag guards. A412, unknown consumed cleanup or drift
stops for owner reconciliation, never clobber/retry.

**Limitation:** a local independent process survives parent exit, NOT laptop
shutdown, network loss or revoked credentials. Expiry closes the exception but
does not prove offline/restored bytes. This is not a guaranteed external cleanup
service; no new runner is authorized. Parent must explicitly review this risk
and actual supervisor behavior before readiness/freeze. No supervisor, review
file or fixed live window is created merely by this implementation.

Parent exclusively owns the real authenticated browser. No browser actions,
keys/headers/auth storage extraction, new identities, roles, networking,
runners, DDL, builds, plans, applies or inference are part of preparation.
Budget remains one scorer attempt, zero completion, zero retries; UNKNOWN
consumes the attempt. APIM-observed IP/context/schema remain runtime gates.

Production Auto still needs genuine gateway-MI runtime proof, source-bound
policy publication and API receipt packaging/enablement, separate persisted
decision-overhead telemetry, broader backend checks, and actual normal UI/API
default-onboarding acceptance. Fixture/ARM success is not scorer proof.
